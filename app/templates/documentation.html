Documentation

How host selection, exclusions, pets, grouping, and assignment balancing work.

What This App Does

ForeKat Admin is a read-only Foreman/Katello client that fetches host inventory, applies local rules, and assigns hosts to local users for patching runs.

The app never writes to Foreman or Katello. It only reads inventory, stores local application data in MariaDB, and renders assignment runs for review and export.

Host Pools

Assignment runs start by choosing one of two literal Katello Host Collections as the eligible host pool:

  • Production for Production runs.
  • Non-Production for Non-Production runs.

Only hosts in the selected pool can be assigned during that run. Hosts outside the selected pool are ignored before any pets or grouping rules are applied.

Host Exclusions

The Host Exclusions List is applied after pool selection and before any assignment work begins.

  • Excluded hosts are removed from the eligible host pool.
  • Excluded pets are not assigned and produce a warning.
  • Excluded special JBoss hosts are not assigned.
  • Excluded hosts never appear in persisted assignment rows.

If every host in the selected pool is excluded, the run completes with a clear warning instead of assigning an empty or misleading set of hosts.

Pets First

Pets always take priority before any grouping or random assignment.

  • Production runs use only Production Pets.
  • Non-Production runs use only Non-Production Pets.
  • A pet is assigned only if it exists in the selected host pool.
  • Pets outside the selected pool are not assigned and are reported with a warning.

Users marked Assign ONLY Pets stay in the run for their pets, but they are excluded from non-pet prefix groups, special JBoss groups, and random hosts for that pool.

Prefix Sequence Grouping

After pets are assigned, the engine groups hosts that share a hostname pattern with a two-digit numeric suffix.

  • The hostname is split at the first dot into the label and domain.
  • The label is split on hyphens.
  • The parser finds tokens that end in exactly two digits and chooses the token that yields the largest contiguous sequence run.
  • If two candidates tie, the leftmost candidate wins.
  • The digits are removed from the chosen token to form the grouping key.

For example, kafka01-stage-bry.platform.is, kafka02-stage-bry.platform.is, and kafka03-stage-bry.platform.is group together, while kafka04-prod-bry.platform.is and kafka04-stage-pkl.platform.is do not join that group because their surrounding tokens change the key.

The current configuration uses min_prefix_group_size = {{ assignment_config.min_prefix_group_size }} and prefix_group_randomness_window = {{ assignment_config.prefix_group_randomness_window }}.

Special JBoss Groups

The app has one explicit special-case prefix group for Production and one for Non-Production.

  • The special hosts are assigned as a single unsplit prefix group when present in the selected pool.
  • If some expected special hosts are missing, the present ones are still grouped and a warning explains what was missing.
  • If a special host is already a pet, pet ownership wins and the special group continues without overriding it.

Balancing and Random Placement

Once pets and prefix groups are handled, the remaining hosts are assigned one by one to the least-loaded eligible user. Ties are broken randomly.

The balance metric is total assigned host count, including pets. The assignment flow intentionally keeps the work synchronous so a run can be reviewed immediately after it finishes.

Export and History

Assignment runs are stored locally in MariaDB. The Assignment Run page shows per-user pets, assigned hosts, warnings, and grouped prefix-sequence details.

The export action builds one spreadsheet per user from the provided Excel template, writes the assigned hostnames into the fixed workbook layout, and returns a downloadable zip archive.
