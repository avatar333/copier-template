Documentation

How to adapt this Copier template into a new Flask project.

What This Starter Does

[[ project_name ]] is a reusable Flask UI scaffold generated by Copier. It provides the page shell, card layout, navigation styling, loading state, and login presentation that you can wire into your own backend.

The template is intentionally presentation-first. It gives you a stable starting point without prescribing database models, background jobs, or app-specific business logic.

Routing Namespace

The rendered templates expect Flask endpoints under the [[ namespace ]] blueprint namespace.

  • Use url_for('[[ namespace ]].dashboard') for the main landing page.
  • Use the same namespace for related content routes such as list, detail, or action pages.
  • Keep admin and authentication routes under their own blueprints if you prefer a different structure.

If you rename the namespace later, update the variable in copier.yml and re-render the template so the generated links stay consistent.

Shared Shell

The shared shell lives in app/templates/base.html.

  • The sidebar and topbar define the recurring page frame.
  • The active nav state is driven by the rendered namespace.
  • The flash-message stack is included in every page.
  • Content pages only need to supply their own body block.

Styling System

The visual system lives in app/static/styles.css.

  • Keep the CSS variables at the top of the file as the primary theme controls.
  • Use the card, button, and table classes instead of inventing new defaults.
  • Use the same utility patterns for empty states, warnings, and form layouts.

Loading Flow

The loading page is split across app/templates/loading.html and app/static/js/loading_action.js.

  • The form submits itself after a short delay.
  • The spinner gives the page an intentional transition state.
  • You can swap the action URL without changing the reusable template shell.

Login Page

The login form is included as a minimal example of the same visual language applied to auth flows.

  • It keeps the form narrow and focused.
  • It works with the same color palette and spacing tokens as the main shell.
  • It can be used unchanged or replaced with your own auth flow.

Extending the Template

Use route_host in generated docs or deployment notes if you want the rendered project to carry a default host value.

Use project_slug for the new repository name, package name, or deployment identity.

Keep the template focused on presentation-layer reuse so new projects can swap in their own backend without fighting the scaffold.
